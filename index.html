01 / What you get

An agent you can trust
with your project.

Totem is a Total.js 5 application that runs on your computer, in a container or on a server. It does not live in someone else's cloud.

01

An agent with tools

It reads, searches, edits, patches and runs commands inside the folder of your project, and it cannot leave it.

Plan · Build 02

A whole application in small tasks

/project turns a request into a short plan and /build walks its tasks one by one: each file is written with only what it needs in front of the model, and checked before the next.

Plan · Tasks · Checks 03

You stay in control

Every file change and command asks first. See the diff of each step, undo it, redo it. Plan mode only reads.

Diff · Undo 04

Any model

Ollama, LM Studio and llama.cpp on your computer, OpenRouter, OpenAI, Anthropic, Gemini and any OpenAI-compatible server. Prompts go only where you send them.

Local · Cloud 05

It knows Total.js

Recipes, the Total.js library and the documentation of Forge for your request, the conventions, and a check of every line it writes: syntax, style and invented functions.

Recipes · Library · Forge 06

Sub-agents

Helpers with their own context, tools and model that the main agent hands a task to. Several work at the same time, and you add your own.

Agents 07

Work in parallel

Sessions in their own git worktree, scheduled prompts that run by themselves, an interactive terminal that survives a reload.

Worktrees · Schedules 08

The hands of a larger model

Claude Code, Codex or another agent writes the plan and reviews the result; Totem writes the files with the model of your computer, through a command or a short API.

CLI · API · MCP 09

Careful with your machine

Secrets never reach the model, .env files ask first, a shared server needs a token, and the Docker image runs without root.

03 / It knows Total.js

The model does not have to
remember the framework.

A small model has seen Express a thousand times and NEWACTION never. So Totem puts the knowledge in front of it, and checks what comes out.

Recipes

Short, exact answers

23 recipes for the common tasks: routes, actions, NoSQL, config, RESTBuilder, auth, CRON, WebSockets, views, system information, jComponent, plugins. They are chosen by the words of your request and work offline.

Library · Forge

The documentation, at hand

The pages that match the request go to the model: the Total.js library (conventions, questions and answers, tested applications, the catalogue of components and icons) and Forge. Totem searches their indexes on your computer, so your prompt is not sent anywhere and there is nothing to allow.

Check

Every line is checked

Syntax, ES5, tabs, names with |, texts as @(English) and no invented functions. What fails goes back to the model.

05 / Install

Three ways,
one minute.

The same application everywhere. Nothing to build.

npm

On your computer

Needs Node.js 22 or newer. Your data goes to a folder of your user.

npm install -g totaljs-totem totem
Docker

In a container

For linux/amd64 and linux/arm64. It refuses to start without an access token.

docker pull ghcr.io/totaljs-es/totem:latest
Source

From the repository

For developing Totem itself.

git clone https://github.com/totaljs-es/totem.git cd totem && npm install node index.js 8000

The guide to get started goes from the install to your first session, step by step, and Help has the answers to the usual problems.

06 / Safe by design

Made to be trusted
with your code.

The agent acts through tools only, and each one is checked before it runs.

  • The project is a boundary. Every path is resolved inside it, symbolic links included.
  • Plan mode is code, not a prompt. It refuses writes and commands, whatever the model says.
  • Secrets stay out. Keys and the token are scrubbed from everything the model sees; .env files ask first.
  • A shared server needs a token. It will not even start without one, and it refuses requests from other origins.
  • Honest limits. The shell and the commands run with your permissions: they protect against mistakes, not against a hostile model.
  • Isolation when you want it. The Docker image runs without root, with your project mounted.
